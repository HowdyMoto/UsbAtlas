USB Atlas 1.5.0 tells you what to fix first, finds USB-C monitors whose USB works but whose picture doesn't, and makes everything on the graph explain itself. It also exports the map as an image to share, and says plainly what Windows does and doesn't report about USB-C.

## What's new

- **Fix first**: a strip above the graph lists the few problems that matter most, worst first, each with the one thing most likely to fix it. Problems with one cause are one entry: a bus-powered hub's power findings and the devices it can't power, or a slow hub and the devices it holds back. Click one to see it on the graph with its explanation open. **Hide** keeps it hidden until the issues change, and it's gone when nothing needs fixing.
- **Export an image**: **Export…** now saves or copies a PNG of the whole topology as drawn, not just what's in view, with when it was scanned, what was found, what to fix first and the legend. Cards carry no serial numbers. The JSON snapshot is still there.
- **Display not showing**: a USB-C monitor's picture travels beside its USB, so its hub, keyboard and mouse can work while it shows nothing. When a USB-C display's hub is connected and no external display shows, the hub says so. It's a warning naming the graphics adapter the display was last shown through when that adapter has no driver, as after a graphics driver update that didn't finish, and otherwise a note on checking the monitor's input, Windows+P and the cable.
- **Everything on the graph explains itself**: hover a connection for its rate, what its width means, and why it's dashed or amber; click it to select its device. The stub that marks a hub's missing USB 3 side says whose side belongs there and leads to what to do. The legend gains that stub and a Color group.
- **USB-C, said plainly**: every USB-C socket now says outright that Windows doesn't report whether it's USB4 or Thunderbolt, carries DisplayPort, or what Power Delivery contract it has. What Windows does report is shown with it: whether the computer has a USB4 host router, any USB4 devices connected through it, and whether USB-C controller firmware (UCSI) runs its ports. A host controller reached through a USB4 or Thunderbolt tunnel is shown as being in a dock, and its tunnel's PCIe link is no longer flagged **Limited by PCIe link**.
- **Measuring real speed**: the Link speed tooltip gives what a fast drive typically moves at best over that link, and the README explains how to measure a drive's real speed and power and what to compare it with. USB Atlas itself still only reads.
- **View controls**: layout, find selection, fit all and zoom are small glyph buttons floating in the canvas's corner, as in map apps, each with its shortcut. New shortcuts: Ctrl+= and Ctrl+− zoom, and Shift+L switches the layout. Auto-refresh moves into a menu joined to **Refresh**, and the search field stands out more clearly from the title bar in both themes.
- The README opens with a short **Getting started**.

### Command line

- `atlascli issues` opens with the same **Fix first** list, in text and as `fixFirst` in JSON.
- New `atlascli displays`, and the `usb_displays` MCP tool: graphics adapters and whether each has a driver, every monitor Windows has known with the adapter it was last shown through, and USB-C displays whose USB is connected but whose picture isn't. Start here when a monitor is dark.
- `atlascli events` labels each event usb, display or restart. Alongside USB events it now lists monitors and graphics adapters coming and going, graphics drivers installed, disabled, updated or reset (Display 4101), restarts a program started (User32 1074) and restarts nothing asked for (Kernel-Power 41), and USB-C controller (UCSI) failures. `--usb-only` keeps the old view.
- `atlascli show` adds `usbCFeatures` for USB-C sockets, `usbC` for hosts (USB4 router, USB4 devices, UCSI), `tunneledOverUsb4OrThunderbolt` for docked controllers, and `typicalBestTransfer` for links, labeled typical, not measured.

## Download and run

Download **UsbAtlas-1.5.0-win-x64.zip**, extract the entire archive, and open **UsbAtlas.exe**. The command line, **atlascli.exe**, is in the same folder. For Windows 10/11 x64. Includes the .NET 10 Desktop Runtime; no separate runtime installation is needed. The command line is also available for Linux as **atlascli-1.5.0-linux-x64.tar.gz** and **atlascli-1.5.0-linux-arm64.tar.gz**; it hasn't yet run on real Linux hardware.

This build is unsigned: Windows SmartScreen will warn on first run, and some organizations block unsigned executables. A SHA-256 checksum is included; see **Download** in the README for how to verify it.

The packaged executable passed its self-tests and the offscreen WPF UI checks in light and dark themes, at default, compact and wide window sizes and in both layouts. The packaged `atlascli` passed its self-test, which runs every command against the sample topology and checks the MCP protocol.

Not yet seen on real hardware: a controller inside a USB4 or Thunderbolt dock, and the Display not showing check with a working graphics driver.
