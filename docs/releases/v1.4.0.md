USB Atlas 1.4.0 runs its command line on Linux, records what Windows' USB hub driver reports in real time, groups devices sharing one piece of hardware, and decodes USB-C alternate modes. Releases are now built and, when a certificate is set up, signed by a script.

## What's new

- The app's two top bars are now one: the title bar holds the app name, a centered search box and the app actions, and layout, zoom and **Fit all** float in the canvas's bottom-right corner, clear of its scroll bars.
- A USB 3 hub's two sides stay wired independently, but devices under linked hub stages now get their own wire each: a shared row beneath the stages, grouped by stage and in socket order, with no crossings and no lines shared between devices.
- **Container ID shared**: when separate hardware reports the same Windows device container, each gets a note. A hub or device named from the USB ID database inside a specifically named container is named after it, such as "Realtek RTS5411 Hub in DELL U2723QE"; Properties gets a **Part of** row, and search matches the container's name.
- **USB-C alternate modes**: a Billboard device's BOS descriptor is decoded on every scan, not only raw ones, giving each alternate mode's SVID (DisplayPort, Thunderbolt, or a vendor name), state, VDO and failure info. An attempted mode that wasn't entered is an **Alternate mode failed** warning naming what's lost and what to do; one never asked for is a note.
- **Device revision**: Properties gets a **Device revision** row (`bcdDevice`, usually the firmware version); `show`, `tree`, `search`, `diff` and `watch` all carry it, so a firmware update shows as a revision change.

### Command line

- The command line also runs on Linux, reading sysfs with no root access needed. It fills the same snapshot, so every command works as on Windows and snapshots from either system load in the other. See **Linux** in the README for what it reads, what it can't, and how to build it.
- `atlascli trace` starts a real-time Event Tracing session on Windows' USB hub driver (USBHUB3) and places what it logs on the topology: connections, port and warm resets, USB 3 links that failed, overcurrent, enumeration retries and failures, rejected descriptors, SuperSpeed devices on the USB 2 bus, U1/U2 refused, and alternate-mode changes, then a count per port, busiest first. `watch --trace` interleaves the same events with `watch`'s own. Needs administrator rights or membership in the Performance Log Users group; the rest of USB Atlas still needs neither.
- The command line was renamed from `usbatlas-cli` to **`atlascli`**: shorter, no hyphen.
- `run-cli.ps1` and the README cover the new commands and the rename.

### Releasing

- `release.ps1` builds the self-contained win-x64 package, with `atlascli.exe` beside the app and the .NET runtime's license and notices included, signs USB Atlas's own binaries when a certificate is configured (a store certificate by thumbprint, or Azure Artifact Signing), verifies every signature, runs both self-tests and the offscreen UI checks from the package, zips it and writes `SHA256SUMS.txt`. `-Linux` adds linux-x64 and linux-arm64 command-line archives. Without signing configured it still packages, with a warning; `-RequireSigning` makes that an error. See **Releasing** in the README. A real signing certificate is still to be chosen (#33); this release is unsigned.

## Download and run

Download **UsbAtlas-1.4.0-win-x64.zip**, extract the entire archive, and open **UsbAtlas.exe**. The command line, **atlascli.exe**, is in the same folder. For Windows 10/11 x64. Includes the .NET 10 Desktop Runtime; no separate runtime installation is needed. The command line is also available for Linux as **atlascli-1.4.0-linux-x64.tar.gz** and **atlascli-1.4.0-linux-arm64.tar.gz**; it hasn't yet run on real Linux hardware.

This build is unsigned: Windows SmartScreen will warn on first run, and some organizations block unsigned executables. A SHA-256 checksum is included; see **Download** in the README for how to verify it.

The packaged executable passed its self-tests and the offscreen WPF UI checks in light and dark themes, at default, compact and wide window sizes and in both layouts. The packaged `atlascli` passed its self-test, which runs every command against the sample topology and checks the MCP protocol.
