USB Atlas 1.6.0 warns before a chain of hubs gets too long, lists devices Windows remembers on other ports and the COM numbers they left behind, shows which devices can wake the computer and what woke it last, and flags drives not using UAS and wireless receivers next to busy USB 3 devices. It also knows a short list of hub, dock and enclosure chips with known problems. Selection is now teal, so blue and red on the map mean only speed; a socket's speed can be set where Windows can't report it; and the app has an icon.

## What's new

- **Five-hub limit**: USB allows at most five hubs in a row, and docks, monitors and keyboards have hubs inside, so chains get there sooner than they look. Properties shows **Hubs above** for every port, device and hub. The fifth hub in a row gets a note, **At the five-hub limit**, naming the chain, since another hub plugged into it won't work. **Hub nested too deeply** now names the hubs a refused device is behind.
- **Remembered devices**: a device without a serial number gets a new Windows entry, and for a serial adapter, Arduino or cockpit panel a new COM number, on each port it's plugged into. Properties lists a device's **Other entries for this device**, placed on the map where their hub is connected, with each one's COM number and when it was last connected. A serial port on a different COM number than before gets a note, **COM number changed**, naming both; a game controller with other entries gets **Remembered on other ports**. Both say how to set the number back and how to remove old entries. Search finds devices by COM number.
- **Waking the computer**: Properties shows **Wakes computer** for every device: On, Off or Not supported, from Device Manager's "Allow this device to wake the computer". A device that woke the computer in the last week gets a note, **Woke the computer**, saying how to stop it. Nothing is flagged just for being able to wake it.
- **UAS**: a **Storage protocol** row says whether a drive uses UAS or the older bulk-only protocol, and whether it supports UAS. A drive that supports UAS but runs bulk-only gets a warning, **UAS not in use**, with a USB 2 link or a hub in between as the likeliest causes. Flash drives and card readers that offer only bulk-only aren't flagged.
- **Known chip problems**: a bundled list of 24 hub, dock and drive-enclosure chips that the Linux kernel works around. It covers links that drop in low-power states, chips that don't come back from suspend, hubs whose ports need slower resets, and enclosures that fail under UAS. Each entry is linked to the kernel line it comes from.
  - Properties shows **Known problems** on every hub and device, such as "No signs here · link power management".
  - Many listed chips work fine, so one gets a note, **Known chip problem**, only when something here looks like its problem. That means dropping and coming back, a slower link, or a device behind it that didn't connect.
  - A drive the kernel keeps off UAS gets **UAS not in use** as a note rather than a warning, since bulk-only may be the safer choice for it.
- **2.4 GHz receivers**: wireless mouse and keyboard receivers, controller and headset dongles and Bluetooth adapters are recognized. One on the same hub as a drive or video device linked at 5 Gb/s or faster gets a note, **USB 3 nearby**, naming it and what to move, since USB 3 gives off noise around 2.4 GHz.
- **Socket speed**: Windows doesn't report a port's top rate, so a motherboard's 10 Gb/s socket was drawn blue until a device linked to it at 10 Gb/s. **Socket speed** under Port in Properties now takes 5 Gb/s or 10 Gb/s or faster, saved with port names; a device that links faster still wins. The legend calls blue **5 Gb/s+**, and every socket entry explains itself.
- **Colors that mean one thing**: selection, search matches, the selected path and focus are now teal, a hue nothing else on the map uses, so the blue and red of USB's socket code mean only speed. Errors use a deeper red than a 10 Gb/s socket's and always come with a glyph on a tinted background, in Fix first and exported images too.
- **Every Properties row explains itself** on hover.
- **USB-C docks**: a Billboard device's slow link is now a note that says it costs nothing, since a Billboard only reports which alternate modes worked. A hub whose USB 3 side is missing while a Billboard inside it reports DisplayPort is explained as the picture taking the cable's fast lanes, not blamed on the cable.
- **Fix first** groups a port refused for bandwidth with its hub's own bandwidth warning, as one fix.
- **App icon**: USB Atlas and atlascli have an icon, in the taskbar, Start and Explorer.
- **Menus** use the app's theme in light and dark, and auto-refresh in the Refresh menu is a toggle switch.

### Command line

- `tree --hidden` lists every device Windows remembers that isn't connected: where it was, its COM number and when it was last connected.
- `show` adds `hubsAbove`, `otherEntries` and `comPort`, `powerSaving.canWakeComputer`, `storage` for drives, `wirelessReceiver`, `knownProblem` for a listed chip, and `ratedMbps` for a socket whose speed you set.
- `issues` opens with when the computer last woke from sleep and what Windows named as the cause.
- `events` lists each wake from sleep, labeled wake, and says when its read limit cut older history short.
- `watch` reports devices and hubs that drop and come back within a second or two, one line per topmost hub with what came back behind it and how long it was gone.
- `raw` reads a hub's own descriptor, so a USB 3 hub shows its SuperSpeed hub descriptor rather than the USB 2-format one Windows fills in.

## Download and run

Download **UsbAtlas-1.6.0-win-x64.zip**, extract the entire archive, and open **UsbAtlas.exe**. The command line, **atlascli.exe**, is in the same folder. For Windows 10/11 x64. Includes the .NET 10 Desktop Runtime; no separate runtime installation is needed. The command line is also available for Linux as **atlascli-1.6.0-linux-x64.tar.gz** and **atlascli-1.6.0-linux-arm64.tar.gz**; it hasn't yet run on real Linux hardware.

This build is unsigned: Windows SmartScreen will warn on first run, and some organizations block unsigned executables. A SHA-256 checksum is included; see **Download** in the README for how to verify it.

The packaged executable passed its self-tests and the offscreen WPF UI checks in light and dark themes, at default, compact and wide window sizes and in both layouts. The packaged `atlascli` passed its self-test, which runs every command against the sample topology and checks the MCP protocol.

Not yet seen on real hardware: a serial adapter's COM number changing between ports, a USB device named as the cause of a wake, a drive running bulk-only, a receiver next to a fast drive on a hub, and any chip on the known-problems list. Each is covered by self-tests.
